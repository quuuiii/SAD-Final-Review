# Ch1 · SDLC, OOAD & UML

> **Lecture basis:** 2026 Ch01 投影片，尤其 p.22–24 的繼承圖與 Unified Process 手寫；113 Final Q15–16。

## Core Definition

- **Systems Analysis and Design (SAD)**：找出業務問題、確認需求，再設計可落實的資訊系統。
- **Systems Development Life Cycle (SDLC)**：以 Planning、Analysis、Design、Implementation 組織開發工作，允許迭代與重疊。
- **Object-Oriented Analysis and Design (OOAD)**：以 Class、Object、Responsibility 與 Interaction 建立系統模型。
- **Unified Modeling Language (UML)**：描述結構與行為的共通建模語言，不是開發方法本身。

## Why & How · Four SDLC Phases

| Phase | Question | Key work |
|---|---|---|
| **Planning** | Why invest? | System Request、Feasibility Analysis、Workplan |
| **Analysis** | What does the business need? | Requirements、Functional / Structural / Behavioral Models、System Proposal |
| **Design** | How will it operate? | Architecture、Database、UI、Class and Method Design |
| **Implementation** | How is it delivered? | Coding、Testing、Deployment、Support |

**Why:** 如果直接從頁面或程式開始，很容易把錯誤的人工流程原樣資訊化。分析先釐清 What，設計再決定 How。

## Development Methodologies

| Approach | Best fit | Pitfall |
|---|---|---|
| **Waterfall / Structured** | 需求穩定、文件與核准要求高 | 晚期變更成本高 |
| **Prototyping / RAD** | 使用者暫時說不清需求 | 原型不能直接取代正式品質驗證 |
| **Agile / Iterative** | 需持續取得 Feedback | 仍要做跨模型與需求追蹤 |
| **DevOps** | 開發及維運需要持續合作 | 不等於省略測試與治理 |

### Unified Process

- **Phases**：Inception → Elaboration → Construction → Transition；老師圖中另標示 Production。
- **Engineering Workflows**：Business Modeling、Requirements、Analysis、Design、Implementation、Test、Deployment。
- **Supporting Workflows**：Configuration and Change Management、Project Management、Environment、Operation and Support、Infrastructure Management。
- **Handwritten insight:** Phases 是開發時間區段；Workflows 會跨不同 Phase 並行。圖上的曲線反映不同階段的相對工作量。

## OO Essentials · Inheritance

| Term | Definition |
|---|---|
| **Class** | 具有共同 Attributes 與 Operations 的物件模板 |
| **Object / Instance** | Class 的具體個體 |
| **Encapsulation** | 把狀態與操作集中，透過介面管理使用方式 |
| **Generalization / Inheritance** | Subclass is-a Superclass，繼承共通成員 |
| **Overriding** | 子類別為繼承的方法提供特化實作 |

**Student / GradStudent / UnderGradStudent（投影片 p.24）**

- **Superclass = Student**：定義 addCourse()、dropCourse()、payTuition() 等共通操作。
- **Subclass = GradStudent / UnderGradStudent**：可直接使用父類別的 inherited methods，**無須重新宣告相同方法**。
- **When to Override:** 只有學費計算規則不同時，才可能在子類別改寫 payTuition()。
- **Source nuance:** 原圖的子類別也列出 payTuition()，可以討論特化，但**不代表所有繼承方法都必須重寫**。

## Concrete Example

**Before:** 各種學生類別複製同一套選課及繳費邏輯，改規則要修改多處。

**After:** Student 集中實作共通的 addCourse()；GradStudent 僅新增研究生專屬操作與需要覆寫的規則。

## Exam Traps & Checkpoints

- **Q15 · Factoring:** 從不同 Classes 抽取共通特徵形成 Superclass。
- **Trap:** 「Subclass 使用 Superclass 的方法必須重新宣告」是 **False**。
- **Trap:** **UML ≠ Methodology**；UML 描述模型，SDLC / Unified Process 說明開發工作安排。
